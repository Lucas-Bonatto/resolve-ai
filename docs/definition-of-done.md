# Definition of Done

All tasks require a focused implementation, explicit types, validation, safe errors, relevant tests, security review, documentation consistency, and verification that was actually executed. Apply the task-specific additions below.

## Backend feature

- Domain ownership is outside FastAPI routes; transport code remains thin.
- Domain errors, bounds, audit/trace fields, and failure paths are defined.
- Ruff, MyPy, focused tests, and the full affected Python suite pass.
- The Python coverage gate remains at or above the configured 85% project floor without excluding production code to hide misses.
- Public contract and architecture documentation are updated.

## Frontend feature

- Strict types match the backend contract; authorization remains server-side.
- Loading, empty, error, narrow-layout, keyboard, focus, contrast, and data honesty are reviewed.
- Component tests, ESLint, TypeScript, and production build pass.
- The web coverage gate keeps statements, branches, functions, and lines above their configured floors; changed behavior has a regression test.
- Playwright runs when workflow or a priority screen changes; meaningful visual changes include review media.

## AI behavior change

- Structured output, evidence validation, time/turn/tool bounds, and safe failure remain intact.
- The prompt reason and provider/model configuration change are documented.
- Affected benchmark and security cases run; results are compared and regressions remain visible.
- `docs/agent-change-checklist.md` is complete.

## New MCP tool

- Purpose, typed input/output, result bounds, risk, validation, timeout, failure, evidence IDs, and audit behavior are explicit.
- Application policy is added where invocable; critical behavior is proposal-only through MCP.
- Normal, malformed, permission, and security tests pass; `docs/mcp.md` is updated.

## Security change

- The relevant invariant is named and threat/abuse cases are described.
- A negative regression test proves the prior failure is blocked.
- Security tests are not weakened, secrets are scanned, and audit behavior is reviewed.
- `docs/security.md` and `docs/security-invariants.md` agree with code.

## Database change

- SQLAlchemy model and Alembic migration are updated and inspected.
- Upgrade and fresh creation are tested; downgrade strategy is understood.
- Foreign keys, constraints, indexes, JSON use, N+1 behavior, seed/fixture impact, and compatibility are reviewed.
- Persistence docs are updated without claiming the in-memory adapter became durable.

## New Chaos scenario

- Initial state, injected failure, symptoms, evidence, expected diagnosis, remediation, risk/approval, terminal states, and reset are deterministic.
- Scenario, orchestration, evaluation, reset, and browser tests cover success and safe failure.
- Demo documentation explains what is simulated.

## Evaluation change

- Cases have expected truth, required evidence, allowed/forbidden tools, approval requirement, and terminal state.
- Metrics are computed from case results, never hard-coded.
- Security targets stay at zero; failing cases remain visible.
- `evals/results/latest.json` is regenerated by the runner and methodology docs are updated.

## External integration

- Default is disabled/mock and local Demo Mode needs no credential.
- Endpoint/resource allowlists, least privilege, secret manager use, network/time/retry bounds, idempotency, audit, and failure isolation are designed.
- Writes have an explicit risk and human approval where critical.
- Mocked boundary tests and opt-in live smoke status are reported honestly.

## Completion review

- Inspect the change set for unrelated work, dead/debug code, placeholders, secrets, generated output, and documentation drift.
- Run the smallest relevant suite plus all checks implied above.
- Update `PROJECT_STATUS.md` only for meaningful completed work, next priorities, decisions, or limitations.
- Report anything not executed and why.
